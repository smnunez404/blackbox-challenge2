# Supuestos y brechas de la réplica local

Este archivo distingue lo observado de los defaults de implementación. Las filas de la especificación en `wiki/arquitectura/especificacion-provisional-reto-2.md` son la fuente del comportamiento observado; los IDs citan `output/experimentos.jsonl`. Actualizar este archivo y las pruebas cuando aparezca evidencia nueva.

| Área | Evidencia disponible | Brecha / supuesto de implementación |
|---|---|---|
| Campo de control `CONSULTA` | Candidata `(17 - 3n) mod 97`, aceptaciones/rechazos IDs 177–181 y análisis offline sin contraejemplos. | Solo probado para cuentas `AC-XXXX` ensayadas. Otros formatos son desconocidos. |
| Campo de control `ANULA` | Candidata `(75 - 3n) mod 97`, IDs 182–184, 195–196. | Solo probado para operaciones `OP-XXXX` ensayadas; la fórmula interna sigue desconocida. |
| Control `DEPOSITO` | Aceptados: `AC-0001;250000;86` y `AC-0002;700;35`; rechazados: `AC-0002;250000;83` y `AC-0002;250000;86` (IDs 14, 172, 186–187, 195). Los rechazos no consumieron OP antes de que el siguiente depósito válido recibiera `OP-0005`. | El modelo admite solo los dos vectores positivos observados; no conoce la fórmula ni el orden de validación con monto/cuenta inválidos. Este fallback conservador puede rechazar casos válidos ocultos. |
| Control `ALTA` | Pares positivos `Lucia;82`, `Mateo;3`, `Lucib;79`, `Lucic;76` y, en V2, `Lucid;73` (IDs 749–750); varios controles negativos; una familia simple de hashes fue refutada en 191–194. | No hay fórmula general ni comparación V1/V2 para `Lucid;73`. El modelo admite solo vectores positivos conocidos y usa E202 como fallback; puede rechazar casos válidos ocultos. |
| Control `TRANSFER` | El vector `AC-0001→AC-0002;40000` acepta control 86 y rechaza el vecino 87 con E202 (IDs 239–240); el mismo estado mostró saldos sin mutación y una siguiente transferencia válida como OP-0003 (242–244). | Solo está confirmado para ese vector. La réplica conserva los positivos observados y rechaza otros como supuesto conservador; no se conoce una fórmula general ni se debe inferir del vecino una regla universal. |
| Controles `DEPOSITO` y `TRANSFER` | DEPOSITO tiene dos vectores positivos y dos negativos documentados; TRANSFER solo positivos/de negocio. | No extrapolar entre comandos ni asumir una fórmula común. Priorizar prueba discriminante para cada comando tras el corte de versión. |
| Monto/formato y tamaño HTTP | No hay resultados registrados para monto cero/negativo/decimal, longitud >1 MB o `Content-Length` inválido. | El modelo responde E501 para monto inválido; el adaptador HTTP limita el cuerpo a 1 MB y mapea longitud inválida/incompleta a E100. Defaults propios, no reglas descubiertas; revisar precedencia. |
| Límite de transferencia V2 | V1 aceptó 100000; V2 responde 422 E506 para ese vector (IDs 44/70 vs. 453/694/733); V2 acepta vectores de 40000 y 50000 (IDs 647/649). | La frontera exacta y su relación con cuenta, día o estado no están determinadas. La réplica rechaza `>=100000` como aproximación conservadora; no se presenta como límite universal confirmado. |
| Saldo en CONSULTA V2 | V1 devolvía un número entero; V2 devuelve cadena decimal con dos cifras y escala observada /100 (IDs 728, 731, 734, 742, 789, 813, 816). | El comportamiento está verificado para saldo cero, positivo y negativo en los vectores observados; no se midieron redondeo ni fracciones de unidad menores que 100. |
| Saldo insuficiente | E507 en una transferencia concreta, IDs 77–80 y 170. | La precedencia exacta frente a límite, inexistencia de destino y control está abierta. |
| Reversas | Transferencia y depósitos concretos anulados, IDs 45–49, 122–131, 184–185, 195–196. | No se observaron todos los casos con fondos ya gastados, operación inexistente/ajena, múltiples anulaciones y conflictos de estado. |
| HTTP | Rutas conocidas exigen auth en muestras probadas; una ruta inexistente devolvió E404 con token válido, ausente e inválido (36, 91–93). `POST /msg` rechazó auth antes de parsear el cuerpo (94, 135). | El adaptador da E404 antes de auth solo para path desconocido; las rutas conocidas con método incorrecto y auth inválida siguen sin matriz completa. Body límite de 1 MB y Content-Length inválido/incompleto → E100 son defaults locales no observados. |
| Autorización no ASCII | No hay observación del original para un header Authorization con caracteres no ASCII. | La réplica lo rechaza como 401 sin cerrar la conexión por excepción de comparación; es una decisión de robustez local, no paridad verificada. Test: `test_non_ascii_authorization_is_rejected_without_dropping_connection`. |
| Monto decimal extremadamente largo | No hay observación equivalente del original. | La réplica evita el límite de conversión decimal de Python y lo dirige al rechazo conservador E202; no representa una regla descubierta. Test: `test_huge_numeric_amount_returns_a_response_instead_of_server_error`. |
| Control decimal extremadamente largo | No hay observación equivalente del original. | La réplica devuelve E202 antes de convertir cadenas numéricas de más de tres dígitos; es una decisión de robustez local, no una regla descubierta. Test: `test_huge_numeric_control_uses_conservative_default_without_crashing`. |
| Conexiones HTTP concurrentes | El README evalúa un solo proceso y compara status/cuerpo; no indica que las conexiones TCP se reutilicen o cierren tras cada request. | El adaptador acepta clientes simultáneos, pero serializa reset y mensajes sobre un único modelo en memoria. Es una decisión de disponibilidad del despliegue, sin cambiar el estado lógico observado. Test: `test_idle_keepalive_client_does_not_block_another_client`. |
| Cambio de versión | Replay V2 de ejemplos oficiales IDs 723–743; replays históricos y secuencias dirigidas posteriores hasta ID 832. | Dos causas funcionales independientes están confirmadas. No se aisló una tercera regla independiente; tipo JSON y escala de `saldo` podrían contarse como dos cambios distintos por el organizador. |

Estrategia local: iniciar con los 20 ejemplos desde reset y pruebas de casos observados; medir por status y cuerpo, no por headers. Una falla del modelo es información para mejorar una regla o declarar un supuesto, no evidencia sobre el servicio original. El runtime nunca debe importar el cliente experimental ni leer el token personal.
